# /inbox

先讀 `AGENTS.md` 的鐵則。**不准寫 `cards/` 的內文。** 這裡只分類，不學、不替使用者寫觀點。

1. 列出 `inbox/*.md`（略過 `.tmp`、`done/`），依檔名（時間）由舊到新處理。沒有就說「inbox 是空的」，結束。
2. 先讀 `glossary.md`，再讀每個檔全文。語音常中英混雜、英文專有名詞常聽錯（例如「Claude」變「cloud」）：
   - 對得上詞彙表的，分類結果寫正確的詞，並在旁邊註明原文聽成什麼。
   - 對不上又看不懂的，照原文引用，標「聽不清」，不要猜。
3. 把內容拆成一則一則，每則歸到一類：
   - **待學**：想搞懂的主題 → 判斷屬於哪個領域（`maps/` 現有的，或新領域），
     加到 `index.md` 的「下一個要學」，格式 `- <主題>（<領域>）`。
   - **來源**：提到某本書、某篇文章 → 加到 `index.md` 的「待讀來源」，之後用 `/add` 收。
   - **觀點**：想法、感受、人生觀 → **寫成一個要問使用者的問題**（例如「你說 X，那 Y 的情況你怎麼看？」），
     加到 `index.md` 的「觀點問題」。不寫結論、不寫內容。
   - **待辦**：要做的事 → 加到 `todo.md`。不派工。
   每則都附來源：`（inbox/done/<檔名>）`。
4. 給使用者看分類表（原文片段 → 類別 → 放到哪），**等使用者確認或修正**後才寫檔。
   使用者改正了聽錯的詞 → 加一列到 `glossary.md`。
5. 寫完把處理過的檔移到 `inbox/done/`（原文不改）。
6. 往 `log.md` 加一筆：`## [YYYY-MM-DD] inbox | N 檔 | 待學 a / 觀點 b / 待辦 c`。
7. commit 並 push（只 stage 動到的路徑）。
